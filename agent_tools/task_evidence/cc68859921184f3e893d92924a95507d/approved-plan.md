## Результат

Устранить падение подготовки сессии при временном таймауте PyPI. Последующие сессии с одинаковыми требованиями устанавливают зависимости из общего локального кэша, сохраняя собственные `.venv`.

## Изменения

- Объединить подготовку в `prepare-start`. Launcher запускает CLI клона через исходный Python (`MCP_PYTHON`); отдельную предварительную установку MCP убрать.
- Создавать общий wheelhouse под `~/.local/share/analytics-toolkit-agent/`. Включать MCP, зависимости проекта, pytest/tox/virtualenv и зависимости editable-сборки. Сам проект устанавливать через `-e` из текущего клона. Такой кэш позволяет устанавливать пакеты без обращения к индексу. [Документация pip](https://pip.pypa.io/en/stable/topics/repeatable-installs/#using-a-wheelhouse-aka-installation-bundles).
- Ключ кэша учитывает Python, ABI, ОС/архитектуру, требования MCP, `pyproject.toml`, `tox.ini` и профиль подготовки. Изменения обычного исходного кода не требуют обновления зависимостей.
- Заполнять кэш под файловой блокировкой во временном каталоге; публиковать атомарно после успешной установки без PyPI и проверки окружения. Одновременные запуски используют один результат. Повреждённый или неполный кэш перестраивать.
- Для сетевой загрузки задать таймаут 120 секунд и 5 connection retries с возможностью пользовательского переопределения. Дополнительно повторять всю команду при временных сетевых сбоях максимум трижды, с паузами 2 и 5 секунд: это покрывает прерывание чтения тела ответа в старом pip. Общий предел сетевого этапа — 15 минут; ошибки разрешения зависимостей сразу останавливают подготовку.
- Показывать ID сессии, этап, использование кэша и повторы. Полный вывод сохранять в приватный журнал; при ошибке выводить краткую причину, путь журнала и команду восстановления. Отметку готовности окружения записывать только после проверок.

## Интерфейс и восстановление

- Добавить локальные команды оболочки: `codex --resume-bootstrap <id>` и `codex --refresh-bootstrap-cache`. Первая продолжает подготовку указанного клона; вторая создаёт новую сессию с принудительным обновлением зависимостей.
- Восстановление разрешать для принадлежащей этому репозиторию сессии в фазе `launching`, на чистой `dev`, без незавершённых Git-операций. Защитить её от одновременного восстановления блокировкой.
- Переводить сессию в `planning` и запускать Codex только после успешного `prepare-start`. Обновить документацию launcher и установленную shell-функцию через существующий установщик. Сигнатуру MCP `prepare_start` сохранить.

## Проверки и допущения

- Проверить холодный кэш, новую сессию с тёплым кэшем при недоступном PyPI и editable-import именно из её клона.
- Покрыть таймаут посреди загрузки, успешный повтор, исчерпание попыток, прерывание, повреждение кэша, параллельные запуски и восстановление существующей неудачной сессии.
- Проверить инвалидирование кэша и отсутствие запуска Codex после ошибки подготовки; выполнить focused и обязательные precommit-проверки, добавить changelog fragment.
- Версии сохраняются до изменения входных требований или явного обновления. Git-синхронизация по-прежнему требует сети.
- Перед реализацией выполнить штатный startup и повторно сверить план: исследование проведено без синхронизации, по разрешённому исключению.
